# Casual 1vs1 matchmaking — v1, 2026-10-21

Purpose: let a registered player find a human opponent without exchanging a code. Input: Find match, cancel search, reconnect. Output: a private filtered room snapshot, first waiting and then the existing 120-second placement phase. Both players keep the normal 30-second battle turns. No bots are silently substituted and no estimated wait or fake player count is shown.

The server supplies UID, initial board state, first player and receive time. `bs_room_match` is invoker and service-only. A transaction queue lock serializes claims; sorted per-identity locks before room-row locks agree with ordinary gameplay CAS. The first available waiting public room is claimed; the other concurrent caller waits in its own room. Active friend rooms are excluded. Queue hosts absent for 90 seconds or waiting for 10 minutes are skipped; the existing timeout worker closes them. These are inherited room lifetimes, not a separate skill/rank system.

Exact request replay is recorded in private matchRequests metadata and never included in DTOs. An uncertain response retains the same request ID. A different search ID from another tab is rejected while an active room exists; it is never accepted as an unrecorded alias that could later create a new search. Normal version/CAS/receipt rules apply after pairing. Cancel-search accepts only an unmatched public queue. If pairing wins the race, cancellation returns QUEUE_MATCHED and the client synchronizes into preparation without closing the room. Ordinary explicit Leave during preparation still cancels the room. Cancellation while waiting returns directly to the room entry screen.

No public queue roster or opponent UID is exposed. Joining a matchmaking room by a discovered code is denied. Snapshots remain membership-only and hide enemy hulls. The normal per-UID write budget applies to searches. Current matchmaking is casual FIFO, no rating/region segmentation, no parties and no 2vs2.

Validation: 14 additional HTTP-client/actual-handler/PostgreSQL-PGlite checks, bringing the total to 111; TypeScript passes. Four local simultaneous searches form two pairs. A separate live SQL test used one waiting synthetic UID and two concurrent connector requests: one claimed the seat, the other created a waiting room. Both test rooms were closed afterward; no Auth accounts were created. These cloud SQL checks do not exercise registered user tokens or deployed HTTP pairing. Normal Edge v7 is active with JWT verification and no QA route; the frontend launcher has not been deployed.

Mobile browser QA at 390px: find, cancel back to entry, find again for A and B, automatic pair into B1 placement. Both canvases remain present; width/scrollWidth 360px.
